Germany’s Accident Black Spots Data Model

How the dashboard’s Power BI model is structured, and how the data was prepared · Data: Destatis Unfallatlas, 2016–2024

Star schema · 6 fact tables · 8 dimensions · built on 2,098,019 injury accidents (Destatis Unfallatlas, 2016–2024) across 400 districts · Source: Destatis Unfallatlas open data (dl-de/by-2-0)

Star schema

All six facts share the conformed dimensions; DimSeverity joins every fact. The four accident facts each sum to exactly 2,098,019 accidents; the two involvement facts each sum to 3,055,312 road-user involvements (multi-counted by design — see the dictionary note).

Relationships (all single-direction, dimension → fact)

  • DimKreis[KreisAGS] → FactKreisYear, FactInvolvement
  • DimLand[LandCode] → FactKreisYear (via DimKreis), FactMonthlyLand
  • DimSeverity[SeverityCode] → every fact
  • DimAccidentType[AccidentTypeCode] → FactKreisYear
  • DimDate[Year] (+Month) → every fact
  • DimLight / DimSurface → FactConditions; DimWeekday → FactTimePattern

Structured & unstructured data

Structured data

Destatis Unfallatlas microdata is a fully structured statistical record — one row per injury accident with coded categorical fields (district, severity, accident type, light, surface, weekday, hour). The model keeps pre-aggregated counts of those records, so every fact sums back to the published total of 2,098,019 accidents.

Unstructured data

District boundaries (kreis_geo.json, 400 features) are geographic shapes for the black-spot map — not free text. The source contains no comments or documents, so no text processing was needed; every value in the model is a published count or code.

How the data was cleaned

  • Coverage caveat (kept visible everywhere): 2016 covers 8 Länder only; the full 16 Länder are present from 2020. Early years are labelled wherever they appear, and the dashboard shows this caveat on the page.
  • The microdata itself is not shipped: every fact is a pre-aggregated count of accidents (AccidentCount), so the four accident facts sum — where the grain allows — back to exactly 2,098,019, verified from the CSVs.
  • Hamburg and Berlin are rolled up from the sub-district coding of the police data to 02000 / 11000; Eisenach keeps its historical code 16056 in the model (it joined Wartburgkreis in 2021) while the map merges it.
  • Column-name variants across the nine yearly files were normalised, and the 2016–2017 goods-vehicle coding is documented in prep.py — analysts who need the microdata can rebuild from the raw yearly files in data/ with that script.
  • DimKreis carries 401 rows (400 map districts + Eisenach’s historical code); Population2024 comes from the Destatis Gemeindeverzeichnis (31 Dec 2024), municipalities aggregated to districts.
